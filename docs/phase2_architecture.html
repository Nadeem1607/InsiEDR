§2 — Core Principles

Plugin Architecture Design Principles

Principle 1: Contract-Driven Plugins

Every plugin category (crypto, feature extraction, detection, storage) defines a Python Abstract Base Class (ABC) with mandatory method signatures and typed return contracts. Plugins are loaded by scanning directories for classes inheriting the correct ABC — no registration boilerplate needed. Each plugin declares a name, version, and enabled flag via class attributes.

Principle 2: Ensemble-First Detection

No single detector produces alerts. The risk aggregator receives deviation scores from all active detector plugins and applies configurable voting logic (default: 2-of-N agreement for Medium, all-agree for High). This directly addresses the "reduce false positives" goal. Each detector outputs per-feature deviation scores enabling explainability at the dashboard layer.

Principle 3: Behavioral Baselines, Not Thresholds

Per the project specification: no static scoring. The baseline engine maintains per-user exponential moving averages (EMA) with configurable decay, standard deviation tracking, and time-of-day bucketing. Detection is always "deviation from THIS user's norm" — never "value exceeds global threshold X." The baseline adapts dynamically as legitimate behavior evolves.

Principle 4: Phase 3 Forward-Compatible Hooks

Every plugin interface includes extension points that Phase 3 modules will consume without modifying Phase 2 code. The storage interface abstracts SQLite behind a DAO allowing PostgreSQL swap. The detection interface supports async prediction for future LSTM. The agent plugin loader supports remote plugin delivery. The risk aggregator exposes a federation API stub.

Abstract Base Classes

Each plugin category is defined by an ABC. Plugins are discovered at startup by scanning the corresponding directory for classes that inherit the ABC and have enabled = True.

from dataclasses import dataclass

@dataclass
class DecryptResult:

class BaseCryptoPlugin(ABC):
    name: str = "base"
    version: str = "0.0.0"
    enabled: bool = True

    @abstractmethod
    def encrypt(self, payload_bytes: bytes, key: bytes) -> bytes:
        """Encrypt payload bytes. Returns ciphertext."""
        ...

    @abstractmethod
    def decrypt(self, ciphertext: bytes, key: bytes) -> DecryptResult:
        """Decrypt and verify. Returns DecryptResult."""
        ...

    @abstractmethod
    def can_handle(self, header_hint: str) -> bool:
        """Return True if this plugin handles the given crypto scheme."""
        ...

from abc import ABC, abstractmethod
from typing import Dict, List
import numpy as np

class BaseFeatureExtractor(ABC):
    name: str = "base"
    version: str = "0.0.0"
    enabled: bool = True

    @abstractmethod
    def feature_names(self) -> List[str]:
        """Return ordered list of feature names this extractor produces."""
        ...

    @abstractmethod
    def extract(self, payload: dict) -> Dict[str, float]:
        """Extract features from raw agent payload.
        Returns dict mapping feature_name → float value."""
        ...

    def extract_array(self, payload: dict) -> np.ndarray:
        """Convenience: returns features as ordered numpy array."""
        feats = self.extract(payload)
        return np.array([feats.get(n, 0.0) for n in self.feature_names()])

§5 — Plugin Registry & Discovery

Plugin Loader Mechanism

server/plugin_registry.py DISCOVERY ENGINE 
# Simplified plugin discovery — no framework, no magic

import importlib, pkgutil, inspect
from typing import Type, Dict, List

class PluginRegistry:
    """Discovers and manages all plugin instances."""

    def __init__(self):
        self.crypto_plugins: List[BaseCryptoPlugin] = []
        self.feature_extractors: List[BaseFeatureExtractor] = []
        self.detectors: List[BaseDetector] = []
        self.storage: Optional[BaseStorage] = None

    def discover(self, package_path: str, base_class: Type) -> List:
        """
        Scan package_path for modules containing classes that:
        1. Inherit from base_class
        2. Are not the base_class itself
        3. Have enabled = True
        Returns instantiated plugin list sorted by name.
        """
        plugins = []
        package = importlib.import_module(package_path)
        for importer, modname, ispkg in pkgutil.walk_packages(
            package.__path__, prefix=package.__name__ + "."
        ):
            module = importlib.import_module(modname)
            for attr_name in dir(module):
                attr = getattr(module, attr_name)
                if (inspect.isclass(attr)
                    and issubclass(attr, base_class)
                    and attr is not base_class
                    and getattr(attr, 'enabled', False)):
                    plugins.append(attr())
        return sorted(plugins, key=lambda p: p.name)

    def load_all(self, config: Dict):
        """Master startup: discover all plugin categories."""
        self.crypto_plugins = self.discover("server.crypto", BaseCryptoPlugin)
        self.feature_extractors = self.discover("server.features", BaseFeatureExtractor)
        self.detectors = self.discover("server.detectors", BaseDetector)

        # Storage is single-active (not multi-plugin)
        backend = config.get("STORAGE_BACKEND", "sqlite")
        storage_map = self.discover("server.storage", BaseStorage)
        self.storage = next((s for s in storage_map if s.name == backend), storage_map[0])

        # Call on_load for detectors that need model files
        for d in self.detectors:
            d.on_load(config)

§9 — Phase 3 Forward Compatibility

Phase 3 Extension Points

The following hooks are built into Phase 2's plugin interfaces but remain dormant (enabled = False) until Phase 3 activation. No Phase 2 code needs modification.

L
LSTM Next-Day Forecaster
PHASE 3
lstm_forecaster.py stub exists in detectors/ with enabled=False. Implements BaseDetector — requires 7-day rolling window from BaselineEngine.get_rolling_window(). Uses PyTorch LSTM trained on per-user feature sequences. Predicts next-day expected behavior vector; deviation from prediction → anomaly. Weight set to 1.5 (highest among ensemble).
P
PostgreSQL Storage Backend
PHASE 3
postgres_storage.py implements BaseStorage with identical interface. Activated by STORAGE_BACKEND=postgres. Migration 002_phase3_federation.sql adds partition-by-month on logs table, materialized views for per-user weekly aggregates, and federation sync tables.
F
Federation API
PHASE 3
The RiskAggregator exposes a get_federation_digest() method (returns anonymized risk metrics per agent). Phase 3 adds api/federation.py blueprint with mutual-TLS endpoints for cross-org threat intelligence sharing. Uses the same BaseStorage interface — no core refactoring required.
A
Autoencoder Detector
PHASE 3
Deep autoencoder trained per-user to learn compressed behavioral representation. Reconstruction error above threshold signals anomaly. Implements BaseDetector — slot exists in detectors/. Requires sufficient per-user history (>200 data points) before activation. Benefits from PostgreSQL materialized views for training data access.
R
Remote Plugin Delivery
PHASE 3
Agent's plugin loader supports a PLUGIN_REMOTE_URL config that fetches signed plugin bundles from the server. Enables centralized deployment of new collector plugins to all 12 endpoints without manual file distribution. Plugin bundles are signed with the server's HMAC key for integrity verification.
D
DLP Integration Extractor
PHASE 3
Third feature extractor plugin implementing BaseFeatureExtractor. Consumes Data Loss Prevention event feeds (file classification labels, sensitivity scores, exfiltration attempt flags). Feeds into existing detectors without modification — detectors that declare required_extractors=["dlp"] activate automatically when the plugin is present.
